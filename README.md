# hxyfront-62011 蹄温预警与训练禁入闭环

由「马术蹄铁修整档案」升级而来的蹄温预警工作台：围绕**蹄叶炎观察**形成
「测温 → 预警禁入 → 降温处置 → 连续复测 → 解除 / 更正失效」的完整闭环。

## 业务规则

1. **每匹马每个蹄位每天只保留一条有效蹄温**（初测 / 更正）。重复提交不覆盖首次结果，
   只作为 `duplicate` 记录归档留痕。
2. **预警阈值**：单蹄温度严格大于 **38.5℃**，或左右前蹄温差严格大于 **1.5℃**。
3. 触发预警的马匹**只能进入蹄叶炎观察，不得列入当日训练**（训练名单自动分栏：
   准予训练 / 观察禁入 / 蹄温未测齐待补测，四蹄测齐才可列入）。
4. 观察档案必须**记录降温处置**；自锚点起**连续两次复测均正常**才自动解除。
   一次异常复测会打断连续计数。
5. **原蹄温被更正后，旧解除立即失效**，档案重开观察、复测计数重置；
   旧记录、旧解除、失效审计事件全部历史留档，不做物理删除。
6. **重复或并发提交沿用首次结果**：每个提交携带 clientToken，结果快照持久化；
   同令牌重试（含刷新页面后）原样重放；不同令牌并发打到同一「马/日/蹄」时，
   后到者归档为重复。写操作经串行队列按到达顺序执行。
7. 列表、训练名单、观察面板共享同一份派生状态；localStorage 持久化，**刷新后一致**。

## 分层结构

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 业务判断 | `src/domain/` | 阈值、观察/解除状态、训练准入等纯函数（无 React、无 IO） |
| 记录存储 | `src/storage/` | localStorage 仓储、串行写队列、幂等索引、演示种子 |
| 页面展示 | `src/components/` | 录入、马匹列表、训练名单、观察闭环、历史留档 |

关键模块：

- `src/domain/rules.ts` — `evaluateTemps`、`horseDayStatus`、`trainingRoster`、
  `releaseSatisfied`、`normalStreak`、`streakAnchor`
- `src/storage/repository.ts` — `submitTemp` / `correctTemp` /
  `recordCooling` / `recordRecheck`
- `src/storage/seed.ts` — 演示数据（观察中、待补测、已解除、更正失效后重新解除）

## 本地运行

```bash
npm install
npm run dev        # 开发服务器，端口 62011
npm run build      # 生产构建
npm test           # 业务闭环验证（44 项：阈值/幂等/并发/闭环/更正失效/刷新一致）
```

页面内置「重置演示数据」和「模拟并发提交」按钮，可直接演示闭环与并发行为。
